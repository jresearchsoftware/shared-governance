## Consumer contract and operator work

The whole-package classification is **5.2.3 -> 6.0.0, MAJOR**, under accepted
PV-002–004 and this producer's per-PR policy. Existing PV-015 already asks for
actual compatibility, but it did not expressly require this historical floor
rationale, range/failure distinction and delivery-source check. The extension
tightens mandatory assessment and forbids a silent competing-source fallback
for resolved delivery. It is not merely an optional example or editorial repair.
Task 74's single-task PATCH exception is inapplicable.

The concrete risks are unnecessary resolver failures and forced upgrade/release
work, false support claims, and silently loading policy other than the consumer's
reviewed selection. Existing lock/provenance, source checks and independent review
provide the cheapest adequate foundation. For a proposed constraint or deliberate
update, operators add the relevant used-contract/history explanation to the
existing change and check the chosen delivery route. Cost depends on the changed
surface and uncertainty; there is no meaningful universal time estimate. Existing
sufficient evidence is reused. There is no recurring startup work, mandatory new
command, full-version matrix, cold installation gate, dependency attestation,
registry, approval service or additional reviewer stage. Stronger accepted local
security and reproducibility constraints remain legitimate.

The public governance flow remains dependency-free. This producer's source and
native lock/slot change to 6.0.0; its separate Relay 3.0.0 dependency keeps its exact
immutable source, Skill, nested closure and projection. All nine referenced
protocol paths and existing section routes remain available. The changed PV
assessment is usable through Relay's existing contract/update guidance and local
bindings without a product implementation change. A compatible major selection
here therefore requires no Relay release or modification to its repository.

Other consumers must assess their own deliberate update and reconcile adoption
and local canonical rules through their own review. Source acceptance, public
publication and consumer adoption remain different events. Later integration
must recompute against then-current accepted main and repeat applicable exact-head
checks/review if the candidate changes. Accepted/published versions remain frozen.
