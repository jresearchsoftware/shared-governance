## Version, producer compatibility and consumer boundary

Package bump: major. Proposed whole-package `1.3.0 -> 2.0.0`. Task 26 deliberately
changes an existing adopted protocol: earlier project-defined Step meanings,
substantive post-start body rewriting and immediate approval of decision-grade
results may require changes. Deliberative owner discussion/Decision is material
mandatory work. Opt-in installation does not make these modifications to an
already adopted topic MINOR; PATCH would also be false under accepted versioning.
No true conflict with another protected shared guarantee was found: preserve
independence, attribution, checks, warnings, proportionality and existing authorized
Direct continuation. The changed allocation/default contract is disclosed here.

The accepted Task 24 native implementation is reused: stable authored package,
exact typed flow pin, dynamic slot route, exporter, versioned local source,
committed lock/slots/index/agent routes and no-bootstrap ready checkout. Only
version-specific literals in its regression fixtures are made version-aware so
negative lock/index/range tests actually mutate the new version. No exporter,
resolver, publisher, workflow, host configuration or credential change is needed.
Four other protocol bytes and frozen/historical content remain preserved.
Candidate materialization is co-committed in this PR and remains proposal data
for this effort; source acceptance, later publication and other consumers' adoption
are separate events.

Future Relay adaptation must resolve the selected strategy before publishing
its native APPROVE, using an authorized non-approving assessment route followed
by owner Decision and exact-head/current-authority validation. A continuation
hold alone acts after approval and is insufficient. Its typed schemas, Writer
reservation/admission, retained manual prompt and stronger identity/merge guarantees
must be reconciled against separately accepted Task 115 state. This Task changes
none of that product or any installed consumer; it defines no new Relay fields.
