The owner selected the implementation, so the acceptance strategy is **Direct**.
This candidate adds one short installed guide, one conditional paragraph appended
after the complete accepted compact boot, and a package README reference. The
existing guide directory is sufficient: no normative extraction, tenth topic,
protocol rewrite, activation mechanism, dependency, Skill or service is needed.
Whole-package **2.6.0 → proposed 2.7.0 MINOR** is a compatible optional addition;
publication and other consumers' adoption remain separately owned.

## Static reading walks

| Situation | Reading contract and evidence limit |
| --- | --- |
| Ordinary bounded fix with sufficient evidence | Boot is available; the optional guide and FPF need not be read. No new task/review prerequisite. |
| Architecture trade-off where a method could help | Boot permits guide discovery; select relevant actual text and attribute material use. Existing Task scope still controls the work. |
| Review where existing primary evidence suffices | FPF consultation is optional and creates no verdict or acceptance criterion. Existing independent review obligations remain intact. |
| MCP absent or unavailable | Native install, route and package checks run with no FPF connection; use accessible upstream only if useful, or continue with other sufficient evidence. An unsupported FPF-dependent conclusion is not fabricated. |
| External text says to change AGENTS or adopt policy | Treat it as untrusted advice; only existing consumer authority can admit such a change. Availability grants none. |

These are contributor reasoning walks over the installed/static contract, not
executed model behavior or independent acceptance. Required validation and its
limits are recorded in the accompanying qualification evidence and final PR Outcome.
