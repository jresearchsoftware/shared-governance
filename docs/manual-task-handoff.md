# Manual Codex task handoff

This example describes this repository's Issue/AGENTS authority. It is a local
client binding and authoring example, not a second Task charter or universal prompt
schema. Root AGENTS explicitly adopts accepted task-handoff through
[native self-adoption](self-adoption.md); editable package source remains
candidate content during authoring.

For governed work here, keep the repository Issue and explicitly linked canonical
decisions current. The owner-admitted work identifies its Step and purpose; local
test/fix iterations remain inside that effort. Future Step allocation, retries
and conversation reuse follow the current Issue's declared instructions. No
stage-versus-attempt counter is inferred from this example.

An execution prompt can be as short as the following historical Task 14 / Step 1
example, based on the owner admission dated 2026-10-11. It illustrates the binding
and supplies no current execution authority:

```text
Task 14 — Step 1 — Shared Task Handoff Protocol
Repository: jresearchsoftware/shared-governance
Canonical Issue: https://github.com/jresearchsoftware/shared-governance/issues/14

Read the complete current Issue, its linked accepted evidence and applicable
repository governance. Execute the admitted Step end-to-end and publish one
reviewable PR with exact-result evidence. Preserve unrelated work and stop for
independent exact-head review within the Issue's current permission boundaries.
```

Use the supported Codex chat-title tool where available, then read the title back.
If rename or read-back is unavailable, state that limitation and retain the
Task/Step/purpose plus Issue link in a supported visible navigation aid. A prompt
does not prove the client's model/effort settings changed. A current execution
prompt also binds the independently verified accepted source-main SHA as described
in self-adoption; candidate root/nested/generated instructions remain proposals.
Subagents supply bounded
implementation assistance only where permitted; they cannot enlarge scope or
provide this candidate's independent acceptance.

For this GitHub binding, commit substantive source and repository-accessible
qualification evidence, use ordinary non-force push, open/update the PR and read
its head back. Publish the protocol's one Outcome in English on the canonical
Issue. Existing independent exact-head review remains required; one account
copying a separate evaluator's assessment creates no native distinct-reviewer
identity or approval.

The 2026-10-11 Task 14 / Step 1 admission authorized implementation, qualification
and the PR/Outcome handoff. It authorized no self-approval, merge, package
publication, consumer change, installation or Issue closure. Later continuation
follows the then-current Issue and review frontier, not this dated example.
[Self-adoption](self-adoption.md) describes the authoring/adoption boundary;
[dated Step 1 evidence](task-14/step-1/README.md) records that qualification.
