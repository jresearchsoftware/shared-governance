# Minimal owner manual follow-up

This follows the [Step 3 Decision](https://github.com/jresearchsoftware/shared-governance/issues/32#issuecomment-6177571849)
and earlier owner-operated trials. The owner controls manual trial projects and
settings; Codex prepares repository artifacts and does not alter live Instructions
or Sources. This runbook adds no separate ceremonial permission checkpoint to
ordinary owner-operated read-only follow-up. Formal adoption, protected actions
and another Codex execution cycle still require their applicable authority.

Start with C3b. Add historical B-H or the small labelled B-U simulation only if
useful for the unresolved question. The unchanged [Step 2 runbook](../step-2/runbook.md)
remains a historical full clean-setup procedure; it is not a mandatory new setup
sequence for each exploratory observation. [Step 3 cases](cases.md) and
[capture sheet](capture-sheet.md) supply the narrow inputs and separate judgments.

1. Record the candidate commit, client surface, visible model/effort, supported
   GitHub access and whether the projects are new or reused. Reused project/chat
   history, Sources and memory are disclosed confounds, not a clean independent
   A/B experiment. Actual serving telemetry may be UNAVAILABLE.
2. For an exploratory check, the owner may use existing temporary projects with
   those limits recorded. If a clean comparison is wanted, use one new comparable
   pair: empty control Instructions/Sources, experiment with the complete reviewed
   Instructions, otherwise comparable supported context and access. No global
   settings change, tool installation or permission expansion is needed to force a test.
3. The owner manually pastes only the sole `markdown` block's contents from
   [the complete experimental Instructions](../step-2/shared-governance-instructions.md)
   at that candidate commit into the experiment's supported field. Reopen and
   record full exact/truncated/changed/unavailable readback. Do not trim critical
   rules or substitute a Source upload/chat message for an unavailable field.
4. Use a fresh chat for the selected case in each arm. Send the same prompt and
   fixture, retain the actual order, and do not copy the other answer or evaluator
   expectations into either arm. C3b contains no explicit request to review.
5. Preserve answers and available tool evidence; record screenshots, response
   text, timing and underlying trace availability separately. If a correction is
   explored, retain the original and label the follow-up rather than replacing it.
6. Judge routing, substantive quality, decision/boundary correctness and qualification
   separately. An autonomous assessment that relies on prior review or lacks primary
   evidence can route correctly while remaining partial. Historical no-action
   reconciliation cannot qualify active unresolved-blocker handling.

B-U is a simulation; keep that label in the prompt and report. Do not create a real
outage, disable access, rerun CI, change credentials or alter a real Task to stage
an active blocker. A naturally occurring unresolved case needs current actual
authority/evidence and the same read-only boundaries; the Outcome cannot grant
its own retry permissions.

For the old owner observations, retain the exact intervention distinction: C2/C3/
C3b used the 4,305-character bootstrap; historical B-H used that old text plus a
short manually appended dispatcher paragraph. The refined Step 3 complete text is
a new candidate, not a retroactively tested version. Neither prompt refinement,
static verifier success nor green CI establishes live model reliability.

Return a concise report with evidence and limits for independent non-approving
assessment and owner disposition. Owner operation of a temporary trial is distinct
from architecture acceptance, shared-topic adoption, consumer migration or formal
PR approval. This execution ends at its canonical Step 3 Outcome and independent
review boundary; Task 32 and PR 33 remain OPEN.
