## Consumer behavior, SemVer and bounded cases

The classification is **6.0.0 -> 7.0.0 MAJOR** under accepted PV-002–004 and this
producer's per-PR policy. 6.0.0 allowed separate close-authorized closure after
all conditions, including post-merge work, and a trusted keep-open policy-release
Decision. The candidate requires final-merge closing linkage or condition-verified
later closure without that policy change. This changes supported operator behavior
and automation; neither PATCH nor optional MINOR fits. Task 74's exception and a
narrow Relay fallback cannot lower the whole-package impact.

The concrete risks are premature closure with publication/work remaining and
indefinite holds despite preauthorized completion. Existing authority, completion
evidence, PR links and protected review/merge mechanisms supply the smallest
correction. Operators choose the existing field, describe actual conditions and
verify them in normal continuation. No extra form, approval, scheduled review,
registry, daemon or test framework is introduced; protected actions remain.

The [Iris walks](../../../packages/development-governance/vibevm/vibespecs/guides/onboarding-examples.md#9-single-field-task-closure)
cover final merge, abandoned/nonmerged PR, multiple PRs, no-PR result, delayed
publication, unmet/wrong-target Apply, historical work and missing/contradictory
metadata without Relay or producer residual rules. These are source-based
behavioral walks, not live GitHub mutations or model tests. Task 84 itself has
