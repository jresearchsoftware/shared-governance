1.0.11 and disposable staging/isolated settings. Verify a chosen public tag's
peeled commit, frozen manifest identity and distribution inventory before setting
an exact version and full Git revision in the root manifest. Tags document the
selection; immutable revisions and native content hashes bind acquired bytes.
Do not use moving main/latest or change global/client settings. Exact pins here
implement the owner's deliberate review of these dated recommendations; they do
not assert that other versions lack functional compatibility.

Preserve the original lock and historical slots before fresh native resolution.
Use staging `VIBE_SETTINGS/registry.toml` for the existing in-tree governance
registry and `vibe install --no-default-registry --no-prefer-local --assume-yes`.
Review the complete lock, selected slots/receipts, root/member INDEX and agent
routes. Transfer only affected generated outputs, retaining historical slots
pruned by the tool. Never hand-edit generated source identities. Run the existing
source/export/native integrity qualification and focused regressions. Git checkout
or restore of the reviewed source and projections is recovery; do not rewrite
frozen releases or resolve a corrupt slot from a different guidance version.
Future flow changes require deliberate consumer review, including scope and local
exceptions; installed updates alone grant no new policy or execution authority.

integration leaves its complete generated Instructions bytes unchanged: existing
