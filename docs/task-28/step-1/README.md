## Reconstruction and bounded canonical sources

Independent review is a judgment about an actual result against independently
resolved authority and primary evidence. Identity and exact-head routing make
that judgment attributable; they cannot prove that it was performed. Review must
discover material omissions as well as changed-file defects, assess affected
behavior and dependencies, and explain what the evidence permits concluding.
Correction requests keep that causal and authority context. A complete first
assessment aggregates reasonably discoverable findings; rereview traces finding
closure, changed behavior, coupled risks and new findings without importing
unrelated baseline debt. The method works for a source PR, research artifact or
operational qualification; their primary evidence and specialized depth differ.

## Alternatives, proportionality and package impact

Considered: (A) enlarge Task Handoff with all methodology; (B) one separately
adopted review contract with short conditional references; (C) optional checklist
plus mandatory technical publication preflight. B is the candidate. A would mix
flow/acceptance with review substance and change an existing adopted topic's work.
C cannot establish that a reviewer understood primary evidence; a service/ledger
would add access, identity, maintenance and false-positive costs. Optional aids
can help navigation but are not sufficient review evidence.

The concrete harm is unsupported acceptance, omissions and repeated wrong-scope
remediation, illustrated by PR 27 and Task 43. Identity/exact-head mechanisms
already protect attribution/currentness; deterministic checks prove narrower
facts. The cheapest added control is an explicitly adopted substantive contract
using existing artifacts/review records, with truthful gap disposition. The owner
admitted this topic; no new technical gate, standing ledger, packet, mandatory
service, review-count ritual or protected live qualification is proposed.

**Package bump: minor — 2.1.0 to 2.2.0.** Whole-package classification includes
new protocol, boot, README and the Handoff reference. Existing topic adoption
does not activate the new obligations; the reference expressly preserves that
condition. Five other protocol files retain accepted bytes. Root human-owned
adoptions are unchanged, so this producer does not silently adopt the new topic
either. A PATCH would understate the new contract; implicit activation or material
mandatory changes in H would require MAJOR. Independently assess that premise.

The candidate contains authored source, generated 2.2.0 registry payload,
installed slot, exact manifest/lock and indexes in one PR. Historical source,
published versions/receipts, old Task evidence, credentials and workflows are
preserved. The exporter admits the seventh topic only from 2.2.0, validates full
payload and tests historical 2.1.0 plus missing/empty/corrupt new-topic incidents.
No capabilities, dependencies or native Skills are added; frozen closure is empty.

Separate consumer migration must pin an independently accepted version, select
the topic, remove genuinely duplicated canonical reusable rules in the same
reviewed change, retain the justified overlays above and qualify its adapter.
For Relay, keep typed identity/verdict/gates and verify strategy compatibility
under its selected accepted product. For DocReview, retain rendered reader gates,
source/confirmation policy and explicit installed-version limits. These are
counterfactual ownership walks, not edits or proof of consumer adoption.
