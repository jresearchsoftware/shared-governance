## Delivery choice and cost

The missing portable result is a usable cross-layer operator sequence. Existing
protocols already own the substantive rules. [The new procedure](../../onboarding.md)
starts from the ordinary onboarding request, discovers actual workflows, recommends
topic choices, reconciles local obligations, separates authorized setup layers,
checks the intended paths and returns an actionable scoped readiness verdict.
The [seven walks](scenarios.md) exercise this sequence, including honest incomplete
results. They are fictional tabletop self-checks, never executed consumer setups.

| Alternative | Coverage and cost assessment |
| --- | --- |
| No change / point only to the GitHub checklist | Low cost, but omits whole-ecosystem topic selection, local/native/client readiness and the useful owner handoff required by the refined Decision. Insufficient. |
| Repository-hosted operator procedure with canonical references | Covers the practical gap without duplicating nine normative procedures or activating policy. One entry in the root README makes it discoverable. Selected. |
| New conditional package protocol | No uncovered portable normative invariant was established. It adds version/materialization/adoption surface and risks redundant authority. Not justified. |
| Skill, onboarding command, configuration service or registry | No demonstrated need; adds implementation/installation/state/permission cost and product coupling. Outside the selected scope. |

The procedure is an optional operator aid outside package source. It is available
through this repository, not added to the installed 2.5.0 payload. It does not
create an automatic invocation on install/update or a new universal gate. Once
invoked, it guides the requested investigation using receiving-project authority;
covered actions need no ceremonial reconfirmation. Separate protected actions
remain with the receiving owner. This trade-off avoids a release merely for
distributing an unneeded normative topic; future package delivery would require
its own justified package change.

Whole-package effect against published 2.5.0: **unchanged**. All package source,
historical exports, native lock/slots/boot, root/member agent instructions,
ChatGPT custom/generated Instructions, toolchain and workflows retain accepted
bytes. No bump, native regeneration, package publication or consumer migration
is needed. The tentative 2.6.0 option was not an instruction to add a topic.
